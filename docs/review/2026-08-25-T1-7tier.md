# T1 Testcontainers·R2DBC 재사용 7-Tier 리뷰

## 검토 범위와 기준

T1은 #792 Epic의 stacked PR train에서 Testcontainers fixture 재사용,
PostgreSQL R2DBC 테스트 활성화, 미사용 Testcontainers 의존성 제거를 담당한다.
구현 범위는 #779, #802, #803이며 composition fixture, R2DBC 예제,
`gateway/api-gateway`, `observability/observability-basic`,
`kotlin/coroutines`, `spring-data/jpa-querydsl`,
`spring-modulith/jpa-demo`와 이 문서만 변경했다. manifest·inventory·PR·merge는
coordinator가 소유하므로 이 lane에서는 수정하지 않았다.

## 변경·요구사항 추적성

| 이슈 | 요구사항 | 구현 및 검증 근거 |
|---|---|---|
| #779 | usage-billing composition fixture가 Bluetape Testcontainers wrapper를 사용하고 custom Kafka topology는 raw fallback으로 유지 | `UsageBillingMicroserviceFixture.kt`가 `PostgreSQLServer(image = "postgres", tag = "16-alpine")`와 `ToxiproxyServer(image = "ghcr.io/shopify/toxiproxy", tag = "2.5.0")`를 사용한다. `KafkaContainer`와 custom listener/network 설정은 그대로 유지했고 wrapper 계약 테스트와 12개 integration test가 통과했다. |
| #802 | PostgreSQL R2DBC 통합 경로를 실제로 실행하고 direct app 실행의 H2 fallback을 유지 | `R2dbcApplication`의 hard-coded `ConnectionFactory`를 제거해 `spring.r2dbc.*` 자동 설정을 사용한다. 공통 테스트는 `@ActiveProfiles("postgres")`와 `PostgreSQLServer.Launcher.postgres` dynamic properties를 사용하며, `application.yml`은 H2를 기본값으로 유지한다. PostgreSQL configuration test와 전체 22개 테스트가 통과했다. |
| #803 | 실제 Testcontainers API를 사용하지 않는 모듈에서 alias를 제거하고 gateway placeholder를 실행 가능한 fallback으로 정리 | gateway, observability, coroutines, jpa-querydsl, modulith-jpa-demo의 unused Testcontainers aliases를 제거했다. gateway Redis `${testcontainers.redis.*}` 값은 `localhost`/`6379` fallback을 갖도록 보완했고, source contract와 전체 gateway 7개 테스트가 통과했다. |

## Raw fallback 및 경계 결정

| 영역 | 결정 | 이유와 증거 |
|---|---|---|
| Kafka broker | raw `KafkaContainer` 유지 | composition fixture가 custom listener, network alias, broker-path proxy topology를 직접 구성한다. wrapper로 대체하지 않았으며 12/12 integration test로 topology를 검증했다. |
| PostgreSQL/Toxiproxy fixture | Bluetape wrapper 채택 | wrapper가 image/tag, mapped port, network, lifecycle 경계를 제공한다. 기존 image pinning과 network 연결을 보존했다. |
| R2DBC runtime | Spring Boot property binding 사용 | 애플리케이션 production path에 test fixture를 하드코딩하지 않고 H2 `application.yml` fallback과 테스트의 dynamic PostgreSQL override를 분리했다. |
| gateway Redis properties | test override + local fallback | gateway test는 WebTestClient와 in-process HTTP stub만 사용하므로 Redis fixture를 추가하지 않는다. 값이 주입되지 않은 local 실행에서도 unresolved placeholder가 남지 않도록 기본값을 제공한다. |

## Known gaps 및 coordinator handoff

- train manifest의 `:gateway-api-gateway:test` selector는 현재 Gradle project
  `:api-gateway:test`와 일치하지 않는다. observability도 manifest의
  `:observability-observability-basic:test` 대신 실제 selector는
  `:observability-basic:test`이다. manifest는 수정하지 않았으므로 coordinator가
  allowlist/selector를 정정해야 한다.
- `kotlin-coroutines`의 2개 skip과 `spring-modulith-jpa-demo`의 4개 skip은
  기존 테스트 상태이며 이번 변경으로 새로 발생하지 않았다. jpa-querydsl의
  1개 skip도 동일하게 기존 상태다.
- jpa-querydsl 실행 중 MapStruct generated source의 `employees`/`departments`
  unmapped target warning이 있었으나 failure는 없었고 이번 dependency 제거와
  무관하다.
- root `./gradlew detekt` aggregate는 T1 범위 밖
  `:commerce-promotion-voucher-campaign:test`가 Docker 환경을 찾지 못해
  `106 failed`로 중단되었다. 대부분의 T1 대상 module에는 module-local `detekt`
  task가 없었고(`:api-gateway:detekt` task not found), composition module의
  `detekt`는 `BUILD SUCCESSFUL`이었다. 따라서 T1 판단은 targeted/full test,
  static scan, diff check와 composition detekt를 근거로 하며 aggregate detekt는
  coordinator 환경에서 재실행해야 한다.
- 이 lane에서는 PR 생성, GitHub approval 확인, rebase merge, branch cleanup을
  수행하지 않았다. 최종 stacked train closeout에서 coordinator가 fresh approval
  확인 후 한꺼번에 rebase merge한다.
