## Raw fallback 및 경계 결정

| 영역 | 결정 | 이유와 증거 |
|---|---|---|
| 일반 JSON serialization/deserialization | shared `Jackson.defaultJsonMapper` | 여러 HTTP/record 경계의 mapper singleton을 통일해 module-local builder와 Kotlin module 중복을 제거했다. |
| canonical input parser | custom `JsonMapper.builder(JsonFactory...)` 유지 | duplicate-key detection, body/depth/name/document length 제한, trailing-token 거부를 한 경계에서 함께 적용해야 한다. `FieldServiceCanonicalizer` KDoc에 `strict canonical input guard`를 명시했고 해당 raw builder는 이 파일 하나뿐이다. |
| plan single lookup | Bluetape generic `findBy` + two predicates + `limit=1` | generic repository를 실제로 사용하면서 plan id/revision unique lookup을 SQL bounded하게 유지한다. |
| plan history lookup | raw Exposed `ORDER BY plan_revision DESC LIMIT` 유지 | generic `findByField` 결과를 모두 메모리에 올리면 history 증가 시 unbounded buffering이 발생하므로 business revision 순서와 `MAX_PLAN_HISTORY` SQL 상한을 보존한다. |
| plan write, CAS, row lock, event append, outbox lease/fencing | raw Exposed SQL 유지 | plan write는 assignments와 함께 원자적으로 저장하고 나머지는 동시성 계약·fencing predicate가 behavior-under-test다. `FieldServiceRepository` KDoc에 범위를 기록했다. |
| HTTP provider call | adapter 추가 없음 | 이 예제의 planner는 deterministic local computation이며 source에 provider call이 없다. 사용하지 않는 direct dependency만 제거하고 transitive test graph는 coordinator 범위 밖에서 강제 제외하지 않았다. |
| test-only benchmark report ID | `UUID.randomUUID()` 유지 | `FieldServiceBenchmarkProbe`의 `runId`는 영속·event·ownership token이 아닌 테스트 보고서 식별자다. production ID/token capability 주장과 분리하고 source inventory에서 허용된 diagnostic metadata로 기록한다. |

### Kotlin 및 assertion 준수

- JSON·ID·Exposed usage는 actual FQCN/API를 source에 남겼다.
- 기존 테스트와 신규 계약 테스트 모두 `io.bluetape4k.assertions`의
  `shouldBeEqualTo`, `shouldBeInstanceOf`, `shouldNotBeNull`,
  `shouldContain`, `shouldNotContain`, `shouldNotBeEmpty`를 사용하며 raw
  JUnit assertion/check는 추가하지 않았다.
- `FieldServiceCanonicalizer`의 raw `JsonMapper`는 strict parser라는
  documented fallback이며, 기본 mapper inventory는 이 파일을 제외하고
  모두 shared singleton을 요구한다.
- production concurrency quick scan에서 새 `GlobalScope`, `runBlocking`,
  `Thread.sleep`, `synchronized`, broad `runCatching` 사용은 추가되지 않았다.
- 새 `FieldServicePlanRecord`는 `Serializable`과 `serialVersionUID`를 선언해
  공통 Kotlin data-class 계약을 충족한다.
- `FieldServiceBenchmarkProbe`의 `UUID.randomUUID()`는 test-only report
  metadata이며 persistent/event/ownership ID가 아니므로 production generator
  inventory와 분리된 documented raw fallback이다.
