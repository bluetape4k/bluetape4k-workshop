## 변경·요구사항 추적성

| 이슈 | 요구사항 | 구현 및 검증 근거 |
|---|---|---|
| #799 | fencing lease를 upstream primitive와 명시적 epoch/bootstrap 계약으로 정렬 | `RedisJobFencingLeaseAdapter`가 `LettuceFencingLease`와 `LettuceFencingLeaseConfig`를 사용하고, `bootstrap`을 acquire 전에 호출한다. resource name은 `ConflictKey` UUID에서 결정하며 workshop 내부 Lua/parser/key/digest 재구현을 제거했다. `FencingToken(epoch, sequence)`를 persistence CAS에 함께 저장하고 승인되지 않은 epoch의 renew/release를 거부한다. leader unit/integration 검증은 11개가 통과했다. |
| #800 | money 계산을 Bluetape capability로 재사용하면서 wire·persistence 계약을 보존 | metering과 DDD order의 계산이 `moneyOf`, `currencyUnitOf`, `bigDecimalValue`를 통해 `bluetape4k-money`를 사용한다. JaVers·JSON·JPA 경계에는 scalar `Money(amount, currency)` wrapper를 유지해 private `MonetaryAmount` 구현 세부사항을 노출하지 않는다. 금액 합산과 HALF_UP 반올림 정책을 고정하고 metering 21개, DDD order 15개 테스트가 통과했다. |
| #801 | virtual-thread executor 소유권을 adapter/runtime 경계에 명시 | operations core는 executor를 주입받아 fanout·idempotency·service가 공유하고, Spring/Ktor runtime이 `VirtualThreads.executorService()`를 생성·소유한다. Ktor는 `ApplicationStopped`에서 job drain 뒤 executor를 닫으며 process-wide default executor를 만들지 않는다. operations core 97개와 Ktor 6개 테스트가 통과했다. |
| #808 | process-wide DB mutation과 JDBC fixture leak 제거 | `JobSafetyJdbcExecutor`와 `MeteringJdbcExecutor`의 `TransactionManager.defaultDatabase` 변경을 제거했다. `TicketJdbcExecutor`는 `AutoCloseable`과 close guard를 제공하고 database를 unregister하며 fixture가 datasource 전에 executor를 닫는다. 기능 동작과 local fixture lifecycle을 분리해 operations·metering·ticket 검증에 반영했다. |

## 경계 결정

| 영역 | 결정 | 이유와 증거 |
|---|---|---|
| Redis fencing | upstream `LettuceFencingLease` 사용 | provider가 epoch를 key domain에 포함하고 bootstrap 결과를 명시한다. adapter는 결과를 workshop port로 변환하며 custom script/parser를 보유하지 않는다. |
| fencing token | `(epoch, sequence)` tuple 유지 | sequence만 비교하면 stale epoch가 통과할 수 있으므로 persistence와 lease adapter가 lexicographic order를 공유한다. |
| money model | scalar wrapper + upstream 계산 | 외부 wire/JaVers/JPA schema는 안정적인 scalar를 유지하고 arithmetic·currency lookup·rounding은 Bluetape API에 위임한다. |
| executor lifecycle | runtime-owned, core-injected | core가 executor를 생성하지 않아 테스트·Spring·Ktor가 소유권을 명시하고 shutdown 시점을 제어한다. |
| bounded Exposed launcher | local fixture boundary 유지 | 현재 upstream에 동일한 bounded Exposed launcher primitive가 없어 `TicketJdbcExecutor` close/unregister만 명시한다. 새로운 공통 abstraction은 추가하지 않았다. |

## Known gaps 및 coordinator handoff

- 전체 저장소 full build와 hosted CI는 이 lane에서 실행하지 않았으며 coordinator가
  모든 child PR을 생성한 뒤 확인한다.
- upstream에 bounded Exposed launcher가 없으므로 #808은 local
  `TicketJdbcExecutor`의 close/unregister 경계로 제한했다. 이 gap을 공통
  Bluetape capability가 존재하는 것처럼 확장하지 않는다.
- Redis integration은 upstream contract에 따라 서로 다른 approved epoch를
  bootstrap한다. bootstrap하지 않은 epoch의 acquire와 old epoch lease의
  renew/release는 실패해야 한다.
- 이 lane에서는 PR 생성, GitHub approval 확인, rebase merge, branch cleanup을
  수행하지 않았다. 최종 stacked train closeout에서 coordinator가 fresh approval
  확인 후 한꺼번에 rebase merge한다.
