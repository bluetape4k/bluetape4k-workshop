## #785 범위 결정

`KinesisStreamServiceTest.kt`는 manifest의 승인된 A2 test anchor이며 기존부터
Bluetape assertions를 사용하므로 소스 변경이 필요하지 않았다. Issue #785가
지정한 production anchors인 `KinesisDemoRunner.kt`와
`KinesisShutdownConfiguration.kt`는 현재 A2 `allowed_paths`에 없다. 따라서
lazy logging 또는 `KLoggingChannel` production 변경을 이 branch에 넣지
않았으며, 해당 production logging closure는 별도 승인된 scope에서 다시
검증해야 한다. 이 경계를 지키기 위해 production code와 manifest를 수정하지
않았다.

## Assertion 재사용과 의도적 fallback

9개 앵커 전체를 다음 금지 패턴으로 재검사한 결과 일치 항목은 0건이다.

```text
org.junit.jupiter.api.assert*, kotlin.test.*, assertEquals, assertNotEquals,
assertThrows, assertTrue, assertFalse, assertNull, assertNotNull, line-leading check(
```

이번 변경에서는 raw assertion fallback을 남기지 않았다. `TicketBrowserContractTest`의
정적 resource 문자열은 테스트 대상 동작 계약이므로 Bluetape `shouldContain`/
`shouldNotContain`으로 표현했다. Spring의 `MockHttpServletRequest` 구성과
Ktor의 route/status API는 framework/protocol surface이며 assertion fallback이
아니므로 그대로 보존했다. 기존 Kinesis/voucher/operations/planning matcher도
provider-gap 없이 유지했다.
