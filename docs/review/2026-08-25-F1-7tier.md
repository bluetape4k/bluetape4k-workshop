## Kotlin pattern 및 bluetape4k 재사용

<!-- reviewed_implementation_oid: 717ca6152b071e5c46d05a18ee8e2f921bfe2963 -->

- `bluetape4k.assertions`: `shouldBeEqualTo`, `shouldBeTrue`,
  `shouldNotBeNull`을 사용해 상태·널 계약을 검증하며 production/test의
  무분별한 `!!`를 제거했다.
- `bluetape4k.junit5.concurrency.TestingExecutors`: 고정 thread pool과
  bounded barrier로 event append/route confirmation의 원자성을 재현한다.
- `bluetape4k.concurrent.virtualthread.VirtualThreads`: JDBC 기준 데이터 조회만
  virtual-thread executor로 보내고 CPU planner executor의 bounded
  admission은 유지한다.
- `bluetape4k-idgenerators`는 현재 production source에서 실제 API를 호출하지
  않고 dependency resolution만 존재한다. 따라서 #784는 `shared-candidate`
  로 남기며, `dependencyInsight` 결과만으로 ecosystem API 재사용 PASS를
  주장하지 않는다. `assertions`와 `junit5`는 같은 BOM 경로의 `1.12.1`이다.
- raw `CyclicBarrier`/`Callable`은 동시성 경계 자체를 명시해야 하는 JDK
  primitive라서 사용했다. executor 생성·종료는 `TestingExecutors`와
  bounded timeout으로 감싸며, 새로운 abstraction/dependency는 추가하지
  않았다.
