# 2.0.0-SNAPSHOT CI 호환성 후속 7-Tier 검토

## 범위와 목표

PR #895(`feat/issue-863-graphio-checkpoint`), PR #897(`feat/issue-864-kinesis-consumer`),
PR #896(`feat/issue-865-strict-image-decode`)가 `bluetape4k-dependencies:2.0.0-SNAPSHOT`
소비자 전환 뒤 같은 CI 실패를 반복하지 않도록 공통 호환성 수정을 한 번에 검증한다.
각 PR은 `develop`을 GitHub base로 유지하고, 아래 follow-up scope는 같은 P0
재사용 train 안에서 branch ref를 exact하게 구분한다.

이번 문서는 새 기능을 추가하는 설계가 아니라 snapshot API·provider 자동 설정·graph
ID 계약의 변경을 기존 예제에 반영한 검증 receipt다. 사용자 승인 없이 merge나
auto-merge를 실행하지 않는다.

## 실패 원인과 수정

| 영역 | 실패 증거 | 수정 | 확인 |
| --- | --- | --- | --- |
| VirtualThreads | snapshot의 `VirtualThreads`가 `io.bluetape4k.concurrent.virtualthread.api`로 이동 | 기존 40개 Kotlin import를 새 API package로 교체 | 세 대표 모듈 `compileKotlin` PASS, 전체 compile PASS |
| Graph/TinkerGraph | 문자열 ID가 `GraphQueryException`을 발생시켜 missing-endpoint 테스트가 실패 | 숫자 형식의 유효하지만 존재하지 않는 `GraphElementId.of("99999999")` 사용 | event-lineage/recommendation/knowledge-graph 테스트 PASS |
| AWS S3 | bluetape4k와 Spring Cloud AWS가 `s3ObjectConverter`를 중복 등록 | Spring Cloud AWS가 S3Client/S3Template을 소유하는 예제에서 `bluetape4k.aws.s3.enabled=false` 설정 | `:aws-s3-spring-cloud:test` PASS |
| Exposed | snapshot `springTransactionManager`가 `DatabaseConfig` 인자를 새로 요구 | `DatabaseConfig`를 주입해 factory 호출에 전달 | 대상 compile PASS, 전체 compile PASS |

## 7-Tier 판정

| Tier | 판정 | 근거 |
| --- | --- | --- |
| T1 요구사항 | PASS | 세 기존 예제 PR의 CI blocker를 snapshot 소비자 계약에 맞춰 수정한다. |
| T2 설계 | PASS | 공통 수정과 PR별 고유 경로를 follow-up scope로 분리하고 branch ref를 고정한다. |
| T3 구현 | PASS | API package import, Exposed 인자, graph fixture ID, S3 property만 수정했다. 새 dependency나 bean override를 추가하지 않았다. |
| T4 테스트 | PASS | 실패 재현 후 대상 테스트/컴파일을 다시 실행했고 전체 compile 762 tasks가 통과했다. |
| T5 통합 | PASS | 세 PR 모두 `develop` base이며 scope overlap은 `stacked-parent-head` 정책과 exact ref로 해소한다. |
| T6 운영 | PASS | fresh coordinator receipt를 발행하고 hosted CI 재실행을 다음 gate로 남긴다. merge는 fresh exact-head 승인 뒤에만 가능하다. |
| T7 회귀·보안 | PASS | S3 자동 설정을 비활성화해 bean override 우회를 피하고, graph ID는 provider가 허용하는 numeric 경계를 사용한다. |

```text
./gradlew :aws-s3-spring-cloud:test --no-daemon --no-build-cache --rerun-tasks --no-parallel --max-workers=1
./gradlew build -x detekt -x test -x integrationTest -x stressTest -x migrationCompatibilityTest --continue --no-daemon --no-build-cache --rerun-tasks --no-parallel --max-workers=1
```

마지막 전체 compile 결과는 `BUILD SUCCESSFUL`, `762 actionable tasks`다.
Gradle warning은 Kotlin 2.4에서 이미 redundant한 compiler flag와 Exposed
migration API deprecation이며 이번 CI blocker가 아니다. 다음 stop condition은
세 PR의 pushed exact head에서 Ecosystem Reuse Gate, compile, smoke, container
checks가 모두 fresh green인지 확인하는 것이다.
